# مقرأة الفاتح (الإصدار الثاني)

منصة لتصحيح التلاوة وتسميع الحفظ: المصحف كاملاً، متابعة حية كلمة بكلمة، ألوان التجويد، ولوحة كاملة للمعلم.

## ما الجديد مقارنة بالنسخة السابقة

| | النسخة السابقة | هذه النسخة |
|---|---|---|
| المصحف | سورة يس فقط | ١١٤ سورة (الرسم العثماني، حفص) |
| التصحيح | مقارنة حرف بحرف في الموضع نفسه، ودرجة لا تقل عن ٣٠٪ مهما كانت التلاوة | محاذاة ذكية تكتشف الكلمة الخاطئة والمحذوفة والزائدة والملتصقة، ودرجات صادقة |
| أثناء القراءة | لا شيء حتى نهاية التسجيل | مؤشر يتقدم مع القراءة وتلوين فوري |
| الحفظ | — | وضع «تسميع غيباً»: النص مخفي ويظهر مع كل كلمة صحيحة، مع تلميح |
| التجويد | قائمة مكتوبة يدوياً لسورة يس، و«درجة تجويد» تقديرية | تلوين آلي لأحكام النون والميم والغنة والقلقلة والمدود في أي آية، وتقييم التجويد يبقى للمعلم بالاستماع |
| القرّاء | العفاسي | ١٤ قارئاً، مع التكرار والتحكم بالسرعة |
| الطالب | واجبات وسجل | + دفتر الأخطاء، وأيام متتالية، وتقييم المعلم وملاحظاته |
| المعلم | تقييم واحد | ٣ معايير (الحفظ، التجويد، الأداء)، تقارير بالكلمات الأكثر خطأً، والطلاب المتأخرون، وتصدير Excel |
| الأمان | كلمة سر المعلم مكتوبة داخل الكود (`1234`)، وقاعدة البيانات مفتوحة للجميع | حساب Firebase للمعلم، وقواعد حماية تمنع الطالب من رؤية قائمة الطلاب أو تعديل الدرجات |
| الصوت | مخزن داخل مستند التسليم | مخزن في مستند منفصل، فقائمة التسليمات سريعة |

## التشغيل

لا يحتاج الموقع إلى بناء (build). هو ملفات ثابتة:

- **Netlify**: اسحب المجلد كاملاً إلى https://app.netlify.com/drop أو اربطه بمستودع GitHub (ملف `netlify.toml` جاهز).
- **على جهازك للتجربة**: من داخل المجلد شغّل `python3 -m http.server 8000` ثم افتح `http://localhost:8000`.

> الميكروفون يعمل فقط على `https` أو `localhost`.
> المتابعة الحية تعمل في Chrome وEdge وSafari. في Firefox يُسجَّل الصوت ويُرسل ليقيّمه المعلم دون تصحيح آلي.

## إعداد Firebase (لمزامنة المعلم والطلاب بين الأجهزة)

الإعدادات الحالية في `js/firebase-config.js` مربوطة بمشروع `quran-c16c8`. إن تعذر الاتصال، يعمل الموقع تلقائياً بالحفظ المحلي على الجهاز.

1. **Authentication ← Sign-in method**: فعّل **Email/Password** و **Anonymous**.
2. **Authentication ← Users ← Add user**: أنشئ حساب المعلم (بريد وكلمة مرور)، وانسخ **User UID**.
3. **Firestore**: أنشئ مجموعة `teachers` وأضف مستنداً معرّفه هو الـ UID، وفيه حقل `name` (اسم المعلم).
   - إن نسيت هذه الخطوة، ستعرض صفحة دخول المعلم الـ UID لتنسخه.
4. **Firestore ← Rules**: الصق محتوى ملف `firestore.rules` واضغط Publish. (القواعد الحالية في مشروعك تسمح لأي شخص بقراءة كل البيانات وحذفها.)
5. ادخل كمعلم، ومن **الإعدادات** اضغط «نقل البيانات القديمة» لنسخ الطلاب وواجبات سورة يس من النسخة السابقة.

### بنية البيانات

```
teachers/{uid}                      { name }
classes/{id}                        { name, createdAt }
tasks/{id}                          { title, classId|'all', surah, from, to, mode: 'hifz'|'recite', due, notes }
roster/{رقم الطالب}                 { name, classId }
roster/{رقم}/subs/{id}              { taskId, percent, counts, statuses, mistakes, transcript, duration, teacher: {hifz, tajweed, ada, total, notes} }
roster/{رقم}/subs/{id}/audio/main   { b64, mime }   ← التسجيل الصوتي (حتى ٥ دقائق)
usage/ai-{YYYY-MM}                  { analyses, failed, billed_seconds, audio_seconds, cold_starts, startup_seconds }  ← يكتبه خادم التحليل
```

## تحليل التجويد بالذكاء الاصطناعي (اختياري)

المجلد `muaalem-space/` خادم Docker يشغّل نموذج [المعلّم القرآني](https://github.com/obadx/quran-muaalem)، ويعيد لكل كلمة أخطاء الحروف والحركات والمدود والقلقلة والغنة. يُنشر على **Google Cloud Run** في مشروع Firebase نفسه.

إعدادات خدمة Cloud Run:

| الإعداد | القيمة |
|---|---|
| مصدر البناء | هذا المستودع، فرع `main`، ملف `/muaalem-space/Dockerfile` |
| المنطقة | `europe-west1` |
| الدخول | السماح بالوصول العام (الخادم يتحقق بنفسه من دخول Firebase) |
| الفوترة | حسب الطلب (Request-based) |
| عدد النسخ | الأدنى 0، الأقصى 2 |
| الذاكرة / المعالج | 8 GiB / 2 |
| مهلة الطلب | 900 ثانية |
| الطلبات المتزامنة لكل نسخة | 1 |
| متغيرات البيئة | `FIREBASE_PROJECT=quran-c16c8` و `ALLOWED_ORIGINS=https://m3naji-droid.github.io` |

بعد النشر ضع رابط الخدمة في `js/firebase-config.js` في `TAJWEED_API.url`.

**عدّاد الاستهلاك:** يسجّل الخادم في Firestore (`usage/ai-YYYY-MM`) عدد التحليلات، والثواني التي احتسبها Cloud Run، ومرات التشغيل البارد. تعرضها لوحة المعلم مع المتبقي من الحصة المجانية (١٨٠٬٠٠٠ ثانية vCPU و٣٦٠٬٠٠٠ ثانية GiB شهرياً) وتكلفة المقطع الواحد بعدها. إن غيّرت المعالج أو الذاكرة في Cloud Run فعدّل `TAJWEED_API.instance` ليبقى الحساب صحيحاً.

**الترخيص:** النموذج مرخّص بـ Quran Muaalem License (QML) 1.0. من شروطه عرض تنبيه الذكاء الاصطناعي قبل أول استخدام وإبقاؤه متاحاً، ومنع الإعلانات. الموقع يعرض التنبيه قبل أول تحليل، ويبقيه متاحاً من رابط «عن المقرأة» أسفل كل صفحة. فلا تحذفهما، ولا تضف إعلانات إلى الموقع.

## حدود يجب معرفتها

- المتابعة الحية أثناء القراءة تعتمد على التعرف على الكلام في المتصفح، وهو مدرب على العربية العامة. أما التجويد فيحلله نموذج «المعلّم» بعد التسجيل إن فُعّل الخادم. النموذج للإعانة، والحكم النهائي للمعلم.
- التلوين الآلي للتجويد يغطي الأحكام الأساسية. بعض المواضع الخاصة (مثل التقاء الساكنين عند همزة الوصل) لا تُلوَّن.

## التنبيهات والإشعارات

| الحدث | لمن | متى |
|---|---|---|
| واجب جديد أو تغيّر موعده/آياته | طلاب الصف | فوراً (خيار للمعلم) |
| تقييم المعلم | الطالب | فوراً، وعند تغيّر الدرجة |
| طلب إعادة التسميع | الطالب | فوراً |
| إعلان | صف أو صفوف أو طالب | فوراً أو في موعد يحدده المعلم |
| تذكير الموعد | من لم يسلّم (أو الجميع) | مساء اليوم السابق للموعد |
| حافظ على سلسلتك | من له يومان فأكثر ولم ينشط اليوم | يومياً في ساعة يختارها المعلم |
| لوحة الشرف | الطالب أو طلاب الصف | يومياً، إشعار واحد على الأكثر |
| نتائج الشهر وشهادات التقدير | كل طالب برسالته | بعد مراجعة المعلم وإعلانه |
| ملخّص التسليمات، ووصول الإعادات، والاستهلاك | المعلم | كل ساعة |

- أوقات الهدوء: لا إشعارات جوال بين ١٠ مساءً و٦ صباحاً، وما يُرسل فيها يصل صباحاً (والتنبيه ظاهر في جرس الموقع فوراً).
- يستطيع الطالب إيقاف تذكير السلسلة وأخبار لوحة الشرف من إعداداته؛ وتبقى بقية الإشعارات.
- على الآيفون تعمل الإشعارات بعد تثبيت المقرأة على الشاشة الرئيسية (iOS 16.4 فأحدث).
